The release adds policy-aware fanout, signed generic interoperability, proactive health, and explicit data and resource lifecycle control while preserving the existing durable-delivery model.

00

The new end-to-end shape

One authenticated event becomes durable state before any destination is contacted. Policy, delivery, health, and lifecycle behavior all work from that shared record.

01

Implementation checkpoints

Each checkpoint is independently useful, but the shared event and delivery model is what makes the combined system coherent.

Policy-based sink delivery decisions

Decide once, explain forever.

Subscriptions can filter normalized event types and severities globally, then narrow individual sinks further. Exclusions win, all configured dimensions must pass, and source-level record-only decisions cannot be overridden.

  • Exact values, wildcard *, and trailing patterns such as pull_request.*
  • Terminal filtered rows with subscription-filter, sink-filter, or source-record-only
  • Admin-visible reasoning without queueing filtered destinations
  • Omitted filters preserve the previous deliver-to-all behavior

Generic events in. Verifiable events out.

  • Stable event identity derived from CloudEvent source and ID
  • Alternate secret references for staged key rotation
  • Outbound signatures, stable idempotency keys, public HTTPS validation, and no redirect following

Proactive operational health

Failures become controlled signals, not leaked exceptions.

Known-route ingress failures, exhausted deliveries, stale work, and retention failures aggregate into fixed-code operational signals with secret-free fingerprints and summaries.

  • KV fallback records survive temporary D1 unavailability and import after recovery
  • Direct alerts bypass subscription fanout, obey cooldowns, and skip an implicated sink
  • Alert failures do not recursively create more alerts
  • The Access-protected health page and guarded bulk redrive operate on live D1 state

Configurable event retention

One policy, two storage systems, explicit verification.

Optional R2 and D1 lifetimes separate object expiration from metadata pruning. Omission disables the corresponding behavior without directly deleting data.

  • Plan, apply, and verify one stable R2 lifecycle rule under events/
  • Preserve unrelated lifecycle rules value-for-value
  • Claim one bounded oldest-first D1 pruning pass per day
  • Return 410 expired only when configured age explains a missing R2 object

Staged resource retirement workflows

Drain first. Archive before deletion. Resume safely.

Subscriptions, sinks, and GitHub fleet repositories gain explicit staged retirement backed by private recovery manifests and persistent phase markers.

  • Sinks remain in retiredSinks and KV until subscription and delivery references clear
  • GitHub fleet manifests record lifecycle state and resumable phase markers
  • Verification checks absence without GitHub pings; partial reruns converge

02

Operator surface

The new behaviors remain opt-in through configuration or explicit phased commands.

Generic interoperability

Both setup commands write and validate local state first, then offer separate prompts for Worker secrets and production KV.

pnpm sink:add automation webhook Guided setup

Reads a public HTTPS destination through concealed input, generates an outbound signing key, writes both values to .dev.vars, stores only their secret names in routes.jsonc, and offers to install and sync them.

pnpm sub:add automation-events cloudevents --sink automation Guided setup

Creates an authenticated CloudEvents route attached to the new sink, generates its private URL slug and sender HMAC, writes the hash-only route locally, and offers to install the HMAC and sync the route.

pnpm cloudevents:send Live test event

Reads the private Hookrelay URL and sender HMAC without echoing, generates a unique valid CloudEvent, signs its exact bytes, and feeds the URL and signature to curl through stdin instead of process arguments.

Retention

R2 lifecycle configuration and runtime KV are separate surfaces. Plan and verify are read-only; only the explicitly confirmed commands write production state.

pnpm retention plan Read only

Reads the current R2 lifecycle rules and previews the exact managed-rule change implied by retention.r2Days, while counting unrelated rules that will be preserved.

pnpm retention apply Production write

Asks for confirmation, adds, replaces, or removes only Hookrelay's managed events/ R2 lifecycle rule, preserves every unrelated rule, and reads it back to verify the write.

pnpm retention verify Read only

Requires the remote managed R2 rule to match routes.jsonc exactly, or to be absent when R2 retention is disabled.

pnpm sync Read only

Validates routes and referenced secrets, then compares routes.jsonc with production KV and prints the desired-state plan without applying it.

pnpm sync -y Production write

Applies the KV plan, making runtime D1 retention configuration active and removing remote route or sink entries that are absent from the complete local desired state.

Individual retirement

Use the same private manifest path for both phases. Staging makes the resource inert; finalization archives recovery data before exact owned-state cleanup.

pnpm sub:retire <name> --manifest <private-file> Stage + confirm

Disables the subscription in local desired state, previews the normal KV plan, and asks before applying the disabled route to production.

pnpm sub:retire <name> --manifest <private-file> --finalize Guarded cleanup

Requires the production route to be disabled, archives its configuration and recoverable authentication, removes only a matching owned GitHub hook and KV route, and cleans only unshared secrets.

pnpm sink:retire <name> --manifest <private-file> Stage + confirm

Requires no enabled subscription or operations alert to use the sink, moves it to retiredSinks, keeps it available to disabled references, and asks before syncing that staged state.

pnpm sink:retire <name> --manifest <private-file> --finalize Guarded cleanup

Proves through D1 that no unfinished delivery references the sink, archives its recoverable values, removes its local and KV definition, and cleans only unshared secrets.
