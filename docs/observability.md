# Sanitized operational telemetry

Hookrelay sends transient producer telemetry to a dedicated Tail Worker, which constructs safe invocation summaries in Cloudflare Workers Logs. Raw receiver paths, query strings, request headers, payloads, email addresses, application log messages, exception text and stack traces are never forwarded by this sanitizer. Durable event, delivery and operation receipts remain the evidence for accepted effects and recovery.

## Source and destination

The producer's `wrangler.jsonc` explicitly disables raw log persistence, automatic traces, Issues capture and Logpush. Its single `tail_consumers` reference selects the sanitizing service. `wrangler.telemetry.jsonc` deploys the separate Tail entrypoint with stored sanitized console logs enabled, invocation logs and automatic traces disabled, no fetch handler, no public ingress and no further consumer. The Tail Worker needs no storage binding, secret or external vendor. `pnpm deploy:check` rejects unsafe producer telemetry before querying D1, including raw persistence, direct exports, automatic tracing, Streaming Tail consumers and a missing or self-targeted sanitizer. The disabled-logging fallback requires both ordinary and Streaming Tail consumer lists to be absent or empty.

Query-string redaction is defense in depth. It cannot remove Hookrelay's bearer path segments or sanitize arbitrary console messages, so enabling producer storage with only `redact_query_string` is unsafe. Disabling invocation records alone is also insufficient because custom log records can receive platform request metadata. The Tail Worker emits newly constructed objects and never serializes raw events or calls `getUnredacted`.

## Reading summaries

Inspect the exact serving producer and telemetry Worker with Cloudflare Fleet. Open the telemetry Worker's Logs, restrict the time window, and filter `event = hookrelay.invocation`. Summary fields contain fixed handler, route, method and outcome categories; HTTP status when available; source event timestamp; validated version ID; CPU/wall time in milliseconds; log, warning, error and exception counters; and truncation/limited-scan flags. Missing or invalid timing and status remain null rather than becoming successful zeroes. Route categories contain no repository, subscription, raw source name or receiver identifier. Queue names, cron expressions and email identities are also excluded.

Warnings and errors count only the bounded inspected console-log prefix; `logScanLimited` discloses an omitted suffix. A `hookrelay.telemetry.coverage` record reports malformed and dropped Tail events when a batch exceeds the processing bound. The sanitizer caps per-batch records and log scanning. It does not forward raw application error messages, so use protected D1 receipts for exact effect diagnosis. Tail delivery and platform retention/sampling can omit records. Missing summaries do not establish health or completeness, and a successful invocation is not proof of notification delivery.

Restrict Workers Logs access to the intended operators. Use Cloudflare's [Workers Logs retention and sampling policy](https://developers.cloudflare.com/workers/observability/logs/workers-logs/), rather than treating the dashboard as a permanent audit archive. Preserve safe correlation references and durable receipts independently when investigating an interrupted operation.

## Deployment and recovery

Creating or deploying the telemetry Worker and attaching a producer are separately reviewed provider effects. The source configuration is not permission to perform them. Use the selected instance's approved account, producer identity and dedicated telemetry service. An isolated rehearsal must use its own service and must never forward to a production telemetry Worker. Keep external exports and raw Logpush disabled. Do not copy production storage bindings into an isolated producer configuration.

After approval, deploy and verify the selected Tail Worker first, using an explicit instance configuration based on `wrangler.telemetry.jsonc`. Then run the producer's read-only `pnpm deploy:check --config <producer-config>` and deploy the checked producer with that same configuration through the [deployment procedure](deployment.md). Inspect provider readback for the exact tail service, raw persistence disabled, traces disabled and the expected serving versions. The configured consumer must already exist; never resolve a missing consumer by enabling raw producer storage.

Before admitting real signed receiver traffic, send synthetic non-secret markers through paths, queries, headers, logs, exceptions and email metadata. Verify both the sanitized message and platform enrichment in the telemetry Worker's stored records, and confirm that the producer has no retained raw records or exports. Exercise failures as well as successful requests. Local unit tests and package builds do not establish hosted platform metadata privacy. Independently review Access/WAF/security logging and the selected ingress policy; this Worker cannot sanitize another capture layer.

For rollback without stored telemetry, set both `observability.enabled` and `observability.logs.enabled` to false and remove the producer's Tail consumers together. Keep raw persistence, automatic traces, Issues capture and exports disabled; neither ordinary nor Streaming Tail consumers may remain. Run the selected configuration through preflight before deployment. Alternatively, deploy a compatible prior sanitizer while retaining the producer's safe policy. These changes do not alter durable receipts or delivery state. Inspect uncertain provider deployment results before retrying. Keep old compatible deployment evidence until replacement readback is verified; deleting a telemetry resource requires separate approval.

## Paid dependency and usage

[Tail Workers](https://developers.cloudflare.com/workers/observability/logs/tail-workers/) require Workers Paid or Enterprise, verified on 2026-11-10. Tail processing is charged for CPU time, with no Tail per-request charge. Normal producer requests/CPU and retained Workers Logs usage remain independent meters. Under [Standard pricing](https://developers.cloudflare.com/workers/platform/pricing/), one million Tail invocations averaging one millisecond of CPU add one million CPU milliseconds, or $0.02 beyond the shared included CPU allowance. This is an illustrative workload estimate, not measured sanitizer CPU or total logging cost.

Workers Free cannot run this Tail pipeline. A supported fallback is to leave producer Workers Logs, tracing and exports disabled and omit `tail_consumers`; use protected event/delivery/operation receipts and account metrics with reduced diagnostic detail. The producer's existing Paid execution ceilings and workload-dependent limits still apply independently, as described in [Free compatibility](../README.md#cost-guardrails-and-free-compatibility). Do not enable raw producer logging to simulate this feature on Free. Measure deployed producer/Tail CPU and log volume before making capacity or cost claims.
